# Desktop app, packaging and releases

## How the desktop app is put together

- `apps/desktop/src/main.ts` (Electron main process) starts the local API **in-process** on `127.0.0.1` with an
  **ephemeral port** and a random **per-launch token**, then opens a window on that same origin.
  The API serves the built web UI itself, so the page and the API share an origin (no CORS) and the token is
  never written to disk.
- `preload.ts` exposes a tiny bridge, `window.classpad` (`api.token`, native-menu events, "show data folder",
  "save report as PDF"). The renderer has `contextIsolation`, `sandbox`, no Node, and a strict CSP.
- Everything is bundled by esbuild (`npm run bundle -w @classpad/desktop`) into `dist/main.cjs` + `dist/preload.cjs`
  - `dist/web/`, so the packaged app needs no `node_modules`.

## Security model

- **No network, enforced:** every request that isn't the local server (or one temp file the app just wrote for the
  report window) is cancelled. Permissions other than notifications are denied; there are no pop-ups or webviews.
- The API requires the bearer token on every `/api` route and rejects unexpected `Host` headers (DNS rebinding).
- Static files are served traversal-safe with a strict Content-Security-Policy.
- Single instance: a second launch focuses the first window; the data folder also has a lock file.

## Data location

The app's `userData` folder is the data directory (override with `CLASSPAD_DATA_DIR`):
`%APPDATA%\Classpad`, `~/Library/Application Support/Classpad`, `$XDG_CONFIG_HOME|~/.config/Classpad`.
Chromium's own files live in its `electron/` subfolder and are excluded from backups.

## Commands

```bash
npm run desktop          # bundle and run the desktop app
npm run desktop:pack     # unpacked app in ./release (fast check)
npm run desktop:dist     # installers for the current OS in ./release
npm run e2e              # Playwright end-to-end tests against the bundle
E2E_EXECUTABLE=release/mac-arm64/Classpad.app/Contents/MacOS/Classpad npx playwright test -c e2e/playwright.config.ts   # against a packaged build
```

Targets: Windows NSIS installer + portable, macOS universal dmg, Linux AppImage + deb + rpm
(`apps/desktop/electron-builder.yml`). Icons are generated by `node scripts/make-icon.mjs`.

## Releasing

Tag a commit `vX.Y.Z` and push the tag. `.github/workflows/release.yml` builds all three platforms and opens a
**draft** GitHub release with the installers and generated notes for you to review and publish.

## Unsigned builds (for now)

Builds are not code-signed, so operating systems show a first-run warning (see the release text for how to
proceed). To add signing later:

- **macOS:** set `mac.identity` to your Developer ID, enable `hardenedRuntime`, add notarization
  (`APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID`), and pass `CSC_LINK` / `CSC_KEY_PASSWORD` secrets.
- **Windows:** provide `CSC_LINK` / `CSC_KEY_PASSWORD` (a code-signing certificate) or Azure Trusted Signing.
- Remove `CSC_IDENTITY_AUTO_DISCOVERY: 'false'` from the release workflow once certificates exist.
  Auto-update is intentionally not included (no network access in v1).

## Known notes

- `npm audit` reports a moderate advisory in the **build toolchain** (electron-builder → roarr → sprintf-js). It
  is not shipped in the app; CI audits production dependencies only (`npm audit --omit=dev`).
